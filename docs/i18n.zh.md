# PCL2 英文支持 / English layer

> Summary: how Swap delivers English on a Chinese-only PCL2, what is covered today, and how to
> extend the dictionary without rebuilding the payload.

---

## 1 为什么是运行时翻译

PCL2 没有本地化资源（surface 索引里只有资源包/版本相关类型，没有 language/translation 类型），
所有界面文本都是中文硬编码。Swap 的做法与它做补丁的方式一致：**不改文件，运行时接管**。

两层组成：

| 层 | 覆盖对象 | 机制 |
|---|---|---|
| Swap 自有 UI | Swap Addon / Swap Settings 页面、提示、对话框 | 构建时 `I18n.T("中文")` 直接取英文 |
| PCL 宿主 UI | 顶部导航、侧栏、设置卡片、按钮、日志行、窗口标题、Tooltip | `HostTranslator` 遍历 WPF 视觉树按词典替换 |

两者共用同一份词典与语言状态。

## 2 语言设置

`设置 → Swap Settings → Language`：

| 选项 | 行为 |
|---|---|
| Follow system | 跟随 Windows UI 语言：中文系统中文，其他系统英文 |
| Chinese | 强制中文 |
| English | 强制英文 |

状态保存在 `<数据根>\ui.json`（`{"language":"en-US"}`）。切换立即生效：
`HostTranslator` 对已接管窗口重放翻译。每个控件/属性同时记录原文、英文值和最后写入值，
切回中文时优先使用该记录；changelog 中新增或重建的宿主文本不会被旧缓存覆盖。

「Translate launcher now / Restore original Chinese」两个按钮用于手动触发/回退，
同时验证翻译层是否工作。

## 3 词典与扩展

- 内置词典：`src/PclDlSwap.Payload/Swap/I18n.cs` 与 `I18n.Extra.cs`，覆盖主导航、下载页、
  设置卡片、帮助页、关于页、反馈对话框、登录/皮肤、联机模块、通用按钮、Swap 页面与启动日志短语
  （v26.3-Alpha 3 为 **610 条精确映射 + 60 条动态短语**；两者有 10 条重叠，去重后为
  **660 条词典键**）。
- 磁盘覆盖：`<数据根>\i18n\en-US.json`，形状为 `{"中文原文":"English value"}`；
  也可把多个 `<数据根>\i18n\en-US\*.json` 语言包放在子目录，启动时按文件名顺序叠加在
  内置词典之上，适合给特定版本补词而不重新打包。
- 短语表：带运行时变量的行（例如 `[时间] 登录加载已开始`、`错误：…`）通过部分替换处理，
  见同一文件的 `PhraseEnglish`。
- 模块语言包：Addon 包内 `i18n/en-US.json` / `zh-CN.json` 通过
  `api.Localization` 读取，生命周期跟随模块，不污染宿主全局词典。打包器使用 `--i18n <dir>`。

可复现审计：

```powershell
.\scripts\i18n-audit.ps1 `
  -PclExe .\test\2.99.1\Plain Craft Launcher 2.exe `
  -Output "$env:TEMP\pcl-i18n-missing.tsv"
```

该脚本直接列出官方 PCL IL 中的中文字符串，按 34 个 `PCL.Page* / FormMain` 类做精确匹配，
并输出缺失表。动态日志仍由短语表另行处理。

翻译只作用于**文本控件**（TextBlock 及其 Run、只读 TextBox、RichTextBox、ContentControl
字符串内容、Header、Window.Title、ToolTip、`Text`/`Info` 属性），不会改写用户输入。
顶栏以外的 WPF 对话框窗口也会在 2 秒兜底轮询中被接管；菜单/DataGrid 的 Header 也纳入翻译。

## 4 Addon 使用

```csharp
// 页面文本：中文原文作为 key，缺少英文时原样返回中文
page.Children.Add(api.Ui.Text(api.I18n.T("我的设置", "My settings")));

// 运行时注册新词条（立即生效）
api.I18n.Register("同步完成", "Sync finished");
api.I18n.RegisterMany(new Dictionary<string, string>
{
    ["同步完成"] = "Sync finished",
    ["已处理 {0} 项"] = "Processed {0} items"
});
string formatted = api.I18n.Format("已处理 {0} 项", 3);

// 对任意宿主子树执行一次翻译 / 回退
int hits = api.Pcl.Ui.Translate(api.Pcl.Ui.MainWindow);
int back = api.Pcl.Ui.Restore(api.Pcl.Ui.MainWindow);
```

## 5 已知限制

1. **不是完整 i18n**：没有复数、性别等语法层，长段落翻译仍是逐条词条；数字格式化由
   `Format()` 交给当前 UI 文化处理。
2. **动态拼接文本**：含运行时变量的整句需要短语表；完全自由的句子会保持中文。
3. **富文本编辑器内容**：只读日志框会翻译，可编辑区域不触碰。
4. **新页面曝光时机**：新出现的控件依赖 LayoutUpdated / 2 秒兜底定时器，最多延迟约 2 秒。
5. 词典未覆盖的 PCL 文本保持中文——这是**渐进覆盖**，不是二值开关。
6. `HostTranslator` 的 LayoutUpdated 路径已改为单次合并调度，后台每 4 秒只做一次兜底扫描；
   Swap Settings 会显示翻译轮次、最近耗时和窗口数，便于继续优化性能。

## 6 API 侧可观测性

```csharp
int entries = api.I18n.Count;                 // 当前词典条数（含磁盘覆盖）
bool known  = api.I18n.Has("联机模块");        // 是否有精确/可归一化词条
bool ok     = api.I18n.TryTranslate("联机模块", out var english);
api.I18n.LanguageChanged += (_, __) => RefreshPage();
```

`LanguageChanged` 在语言真正变化并完成界面重放后触发；订阅者异常由平台隔离，不会阻断其他
addon。

## 7 验证记录（v26.2 / v26.3）

- 精确词典为 610 条，另有 60 条动态短语（10 条与精确表重叠）；`scripts/i18n-audit.ps1`
  只把精确映射用于覆盖率，对官方 2.99.0.1 的 34 个页面类测得
  **1692 条不同中文 `ldstr` 中精确命中 388 条（22.93%）**。这个全量口径包含日志、异常、
  崩溃分析和彩蛋文本，不能当作“可见 UI 完成度”；此前 89.2% 不可复现，已撤回；
- 语言切换改用逐控件原文账本，动态短语和重复英文值也能可靠回退；
- `RegisterMany`、`Format`、`TryTranslate` 与 `en-US/*.json` 多文件语言包可用；
- `--pcltest` 覆盖 API 1.8-1.11 英文 API；`--uitest` 覆盖原文/英文/回退三态和
  Table/EmptyState/CodeBlock/Scroll；
- Swap Settings 新增运行诊断时间线，英文切换后的页面仍保持原有布局。
- 最终真机确认反馈分流弹窗正文、内置模块说明和 Demo 页面全部英文化；
  v26.2 正常/权限/安全模式四轮均为 `ok=73 fail=0`。
- v26.3 功能作用域新增 `nameEn` / `descriptionEn`，模块详情按当前语言选择并在缺失时
  回退中文；API 1.11 的包资产、模块语言包、Appearance/Window 与四个新前端同样使用显式双语，
  真机 `v26.3-Alpha 3` 正常启动自检为 `ok=84 fail=0`。
